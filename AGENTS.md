# Continuidad del proyecto

- Antes de trabajar, leer `BITACORA.md`, `README.md` y `VERIFICATION.md`.
- Al terminar cada tarea, actualizar el estado actual de `BITACORA.md` y agregar una entrada al historial: solicitud, cambios, verificaciones ejecutadas, resultado y pendientes.
- Conservar las entradas anteriores. Distinguir verificaciones históricas de las realizadas en la tarea actual; no afirmar que algo fue probado si no se ejecutó.
- No guardar secretos, contraseñas, JWT, API keys ni contenido de `.env` en documentación o salidas.
- Trabajar con Node.js y PostgreSQL locales. El usuario indicó no ejecutar Docker por ahora; conservar sus archivos para verificación futura.
- Mandaria es independiente de Coita Eats. No importar su código ni acceder a su base de datos.
- No implementar funciones de V1.1+ sin una solicitud que amplíe el alcance.
- Cuando se cambie la versión del paquete, sincronizar `package.json` y las versiones del proyecto raíz en `package-lock.json`. El número de versión no acredita por sí mismo el cumplimiento de la Definition of Done.
