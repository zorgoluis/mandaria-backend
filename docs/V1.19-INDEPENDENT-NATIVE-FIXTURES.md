## Escenarios y cuentas

Todos los Drivers tienen cuenta activa y capacidad independiente APPROVED, con vehículo propio ACTIVE. Excepto driverD, están libres al entregar. La pertenencia a flotilla es contexto dual real; no convierte el vehículo de flotilla en uno independiente.

| Escenario | Alias | Entregado | Pasos reservados para APP |
|---|---|---|---|
| take-normal | driverA | Oferta OPEN; saldo100 | TAKE con clave; comprobar asignación/award únicos |
| competition | driverB / driverK | Ambos libres, vehículos propios y saldo100 | Competir por el mismo despacho; consultar sólo recibos propios |
| insufficient | driverC | Oferta OPEN; saldo13 frente a costo14 | TAKE debe rechazar; reconciliar/cerrar intento sin efectos |

| close-take | driverF | Oferta OPEN; sin intento | Retener POST antes del servidor, cerrar misma identidad, enviar tardío y verificar rechazo |
| close-release | driverG | Oferta OPEN; sin intento | APP hace TAKE; retiene RELEASE, cierra intento y prueba POST tardío sin liberar/refund |
| legacy-readonly | driverD | FLEET ACTIVE/LEGACY, RECIPIENT; sin ejecución ni hitos | Sólo lectura; no consumir, liberar ni entregar |

`admin` es SUPER_ADMIN; `operator` es administrador de la flotilla sintética. Las resoluciones excepcionales físicas no quedan autorizadas por este preparador: coordinar su prueba expresamente. Las etiquetas de escenarios son reservas de pruebas, no aislamiento implementado por el producto: todos los independientes elegibles pueden ver el mismo mercado sintético. Seleccionar siempre los IDs del manifiesto, no la primera oferta.

## Operación reproducible

Desde la raíz del backend:

```powershell
node scripts/prepare-native-v119-independent.mjs start
node scripts/prepare-native-v119-independent.mjs snapshot
node scripts/prepare-native-v119-independent.mjs stop
```

`start` es para un entorno detenido: identifica el directorio/SQL y rechaza un puerto ocupado; no mata otro proceso. `stop` comprueba PID, launcher, base y directorio antes de parar exclusivamente este entorno. Conserva todos los datos.

`init` fue usado una sola vez sobre directorio ausente/puertos libres para migraciones normales y bootstrap del administrador. `prepare` usa APIs, pasos persistidos y claves; si ya terminó, sólo verifica. Ante resultado incierto de una escritura, conserva `pending` y se detiene: no borra el marcador ni duplica operaciones automáticamente. No correr `init` para renovar escenarios vencidos o consumidos.

```powershell
node scripts/prepare-native-v119-independent.mjs prepare
node scripts/prepare-native-v119-independent.mjs verify
```

Estas dos verificaciones exigen estados iniciales y deben fallar después de operaciones Android. Usar `snapshot` para capturar deltas posteriores; nunca restaurar huellas iniciales mediante SQL. No hay reset ni bypass de constraints.
