## Diseño de las pruebas nuevas

`test/check-c3-authorized-acceptance.e2e-spec.ts` conserva escenarios C2 y los ejecuta con **dos aplicaciones Nest y dos PrismaService distintos**, alternando HTTP entre ellas. Obtiene tokens por `/integrations/token`, con credenciales sintéticas hasheadas. Auth, idempotencia, consumo durable A5, conversión, aceptación, snapshots y persistencia son reales. Sólo routing es doble de negocio. Se desactiva el ThrottlerGuard de esas aplicaciones de prueba para concentrar carreras; el guard de autenticación/scopes sigue real. No se acredita rate limiting ni se cambia configuración compartida del runner.

Cuotas de A5 y fingerprint se configuran coherentemente en la base/instancias aisladas; no se omite su admisión ni su contabilidad. Emisión y replay verifican un permiso durable/una ejecución/una ruta; conversión y accept verifican cero adicionales. La unitaria C3 simula exclusivamente el reloj de la DB para igualdad exacta de expiry de MQ, JWT y credencial; no afirma detener el reloj físico de PostgreSQL.

Locks observados mediante `pg_stat_activity`, transacciones y barreras deterministas; no se acredita una carrera sólo por lanzar Promise.all. Completions/cancelaciones de orden forzado usan helpers transaccionales reales y pools independientes; no todos los escenarios de completion son peticiones HTTP. Pérdida de respuesta: se fuerza fallo en la lectura posterior al commit; otra aplicación recupera por la misma key. No representa un corte TCP real.

### Límites de confianza y tiempo

SQL comprueba relaciones, estados y hechos; no verifica la firma JWT ni consentimiento humano. Un escritor capaz de fabricar la atestación completa puede construir evidencia estructuralmente válida. DDL/superusuario fuera de garantía.

Ensayo nuevo: escritor SQL construye **todo** el conjunto válido, evalúa `SET CONSTRAINTS ALL IMMEDIATE` antes de expiry y espera hasta después para hacer commit. PostgreSQL lo admite, conserva expiry/acceptedAt y no duplica recursos. Es el límite explícito C1/C2, no garantía de commit físico antes de expiry. HTTP conserva evaluación diferida y revalidación temporal. No se cambió el contrato para aceptar el resultado.
