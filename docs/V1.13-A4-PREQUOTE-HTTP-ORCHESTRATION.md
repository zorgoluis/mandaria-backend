## Contrato HTTP

Ambas rutas requieren Bearer B2B vigente. Scopes nuevos `prequotes:create` y `prequotes:read`; sólo se amplía el catálogo. No se otorgan a filas existentes ni se cambian sus credenciales. JWT humano no es válido. Se mantienen el formato de errores global y `X-Request-Id` generado por servidor.

### POST /api/v1/delivery-prequotes

`prequotes:create`, `Idempotency-Key` obligatorio de 8–255 caracteres ASCII visibles (sin espacios). Campos desconocidos rechazados, incluidos integrationClientId, financialContext, referencias, contactos, direcciones y bancos. Servicio inmediato LOCAL_DELIVERY, paquetes FOOD, conditionsVersion obligatorio igual a 1. El normalizador A3 es la única autoridad de validación y canonicalización; los DTO HTTP describen ese contrato, no implementan reglas paralelas.

## Configuración y presupuesto temporal

`.env` no modificado. `.env.example` documenta:

| Variable | Default | Validación |
|---|---:|---|
| PREQUOTE_ENABLED | false | true/false; necesario pero insuficiente para emitir |
| PREQUOTE_VALIDITY_MS | 900000 | entero 1–86400000 (15 min por defecto) |
| PREQUOTE_LEASE_MS | 90000 | entero 1–300000; además debe cubrir presupuesto de routing + margen |
| PREQUOTE_MAX_ATTEMPTS | 3 | entero 1–5; A3 congela presupuesto al reservar inicialmente |

Presupuesto conservador incluso con local_fake: `GOOGLE_ROUTES_TIMEOUT_MS * (GOOGLE_ROUTES_MAX_RETRIES + 1) + 100 * retries * (retries + 1) + 15000`. Incluye todos los timeouts y backoff lineal del adaptador Google existente más 15 s para publicación. Configuración menor rechazada al arrancar, aun deshabilitada; no amplía límites A3. Antes de routing se comprueba contra el reloj DB que el lease siga siendo propio y tenga todo ese presupuesto restante. Un permiso/admisión lento no autoriza una llamada con lease insuficiente.

No hay renovación, bucles de routing del orquestador ni retries externos a la política del adaptador. Un intento durable invoca una vez calculateRoute, que conserva sus retries existentes. Contención, demoras de DB/event-loop o un adaptador futuro que incumpla su presupuesto pueden vencer el lease: fencing impide publicación tardía, no promete cancelación instantánea de red ni exactamente una llamada ante crash. A5 deberá contabilizar llamadas/consumo ambiguo incluyendo retries del adaptador.

Vigencia se calcula desde publicación A3 con clock_timestamp DB después de locks. No usa RatePlan.quoteValidityMinutes. Lecturas de expiración usan reloj de aplicación; relojes de hosts deben permanecer sincronizados con PostgreSQL.

## Orquestación y transacciones

1. IntegrationGuard autentica, valida JWT y consulta estado actual de IntegrationClient/credencial; IntegrationScopesGuard exige scope. El normalizador A3 valida antes de tocar reservas/routing.
2. `inspect` nuevo en PrequotePersistenceService lee key/metadata/snapshot bajo REPEATABLE READ: conflicto, éxito, fallo terminal, en curso o disponible. No reserva ni incrementa intentos, ni cambia a FAILED un lease agotado observado. No crea otro registro/namespace.
3. Replay devuelve evidencia. En curso retorna conflicto con Retry-After al vencimiento del lease. Terminal conserva una respuesta de error, no una consulta de recurso inexistente.
4. Para trabajo nuevo/recuperación: flag, reautenticación con el mismo token, permiso de consumo. Si deniega no hay reserva. Se comprueba flag otra vez después de admitir y antes de reservar.
5. reserve A3 serializa la única key y adquiere/revalida resultado. Si otro ganó durante admisión, se finaliza el permiso sin routing. Un único adquirido continúa.
6. Transacción corta REPEATABLE READ prepara zona/tarifa mediante prepareQuotePricing A2. Se cierra completamente antes de llamar proveedor.
7. Reautenticación, comprobación de habilitación, permiso.start, reautenticación, presupuesto restante DB, nueva comprobación de habilitación. Routing recibe exclusivamente latitud/longitud canónicas, sin type/sequence ni cuerpo completo. No mantiene locks/transacción durante la llamada.
8. Reautenticación después de routing y antes de publicar. publish A3 vuelve a preparar/revalidar configuración bajo sus locks y compara IDs; evaluateQuotePrice calcula importe sin Quote ficticia. Persiste evidencia y éxito atómicamente con fencing.
9. Si falla, fail sólo puede cambiar el lease propio vigente. Un ejecutor vencido no puede sobrescribir sucesor. Si se perdió respuesta del COMMIT, se consulta protocolo durable y sólo se retorna éxito tras verificar evidencia comprometida y reautenticar.
10. finally finaliza permiso una vez por el orquestador; la implementación A5 debe hacerlo idempotente y recuperable. Un error de finalización se registra con código seguro y no transforma un COMMIT confirmado en un falso fracaso.

Cambios durante routing: zona/tarifa ausentes, ambiguas, inválidas o IDs cambiados en publicación → PREQUOTE_CONFIGURATION_CHANGED, reintento con misma key dentro del presupuesto. No hay recálculo de routing automático. Una edición de nombre/geometría que conserva cobertura y configuración válida se revalida y congela al publicar; no se congela anticipadamente una lectura administrativa incoherente. Cambios después de publicar no alteran snapshot.

Revocación: se reutiliza authenticate, incluidas firma/expiración, estado de integración, estado/revokedAt/expiresAt de credencial e intersección scopes token/DB. No se registra token. Se vuelve a comprobar antes de trabajo externo y de publicación. No se toman locks de autenticación compartidos con administración; una revocación entre última comprobación y llamada/COMMIT puede competir. No se promete atomicidad con hechos externos o cancelación de llamada ya enviada.

## Barrera A5: contrato mínimo pendiente

Token DI PREQUOTE_CONSUMPTION → UnavailablePrequoteConsumption siempre devuelve denegado. No hay implementación permisiva en src, bandera de bypass ni condición NODE_ENV/local_fake. Sólo la suite sustituye el token por un doble.

- `admit(integrationClientId)` devuelve denegación (retryAt opcional sólo si justificable) o permiso. A5 debe implementar admisión compartida, cotas por integración/global y concurrencia entre instancias. No se aceptan cantidades o permisos enviados por cliente.
- `permit.start()` debe registrar durablemente consumo potencial **antes de resolver**. Si falla/no resuelve, no se llama routing. Crash después de registrar y antes/después de red es ambiguo y no debe liberar presupuesto como si fuera consumo cero.
- `permit.finish({routingStarted,published})` informa si calculateRoute llegó a iniciarse y si se verificó publicación exitosa. Debe ser idempotente y seguro ante reintentos/fallo del proceso; A5 necesita identidad interna de permiso y reconciliación/leases propios en su implementación, no en la API pública.
- El booleano routingStarted no reemplaza la marca durable start ni certifica cero facturación externa. A5 deberá conservar consumo/ambigüedad cuando no tenga prueba suficiente. GET/replays no piden admisión.
- No hay cuotas, contadores en memoria disfrazados de protección compartida, consumo simulado de producción ni nuevo worker en A4. Throttler HTTP global sigue vigente y no es el control de coste A5.
- Desactivación antes de routing impide iniciarlo. Si ya empezó una llamada autorizada se permite terminar/publicar con fencing y autenticación vigente; no otra llamada/recuperación al observar desactivación. No se promete interrumpir una llamada externa ni coordinar instantáneamente flags entre procesos.

## Mapeo público de errores y recuperación

Todos conservan statusCode/code/requestId/message/errors/timestamp/path del filtro y X-Request-Id. No mensajes internos del proveedor, cuerpos, SQL o secretos.

| Resultado | HTTP / code | Recuperación |
|---|---|---|
| acquired + publicación | 201 | Idempotent-Replayed false |
| succeeded | 200 | Replay sin routing, incluso EXPIRED |
| intención/cuerpo/operación incompatible | 409 / HTTP_409 | No reutilizar key para otra intención |
| in_progress | 409 / PREQUOTE_IN_PROGRESS | Retry-After en segundos hasta lease; repetir misma key |
| lease perdido | 409 / PREQUOTE_LEASE_LOST, o estado durable vigente observado | Nunca éxito sin evidencia comprometida |
| presupuesto temporal insuficiente | 409 / PREQUOTE_LEASE_BUDGET_INSUFFICIENT | Misma key, intento acotado; terminal PREQUOTE_FAILED al agotarse |
| lease abandonado sin intentos restantes | 409 / ATTEMPTS_EXHAUSTED | Terminal sin routing ni mutación por inspect |
| fallos reintentables agotados/terminales | 409 / PREQUOTE_FAILED | Terminal; no Retry-After. Evita ocultar terminalidad tras 503 sanitizado |
| configuración cambió al publicar | 409 / PREQUOTE_CONFIGURATION_CHANGED | Misma key dentro del presupuesto, sin oferta parcial |
| routing indisponible/timeout | 503 / ROUTING_UNAVAILABLE | Misma key dentro del presupuesto; agotado → PREQUOTE_FAILED |
| ruta inexistente/distancia sin banda | 422 / ROUTE_NOT_FOUND o DISTANCE_NOT_SUPPORTED | Terminal |
| cobertura inicial inválida | 422 / OUT_OF_SERVICE_AREA o CROSS_ZONE_NOT_SUPPORTED | Terminal |
| configuración inicial ausente/inválida/ambigua | 503 / RATE_CONFIGURATION_UNAVAILABLE, RATE_CONFIGURATION_INVALID o SERVICE_ZONE_AMBIGUOUS | Acotado; terminal → PREQUOTE_FAILED |
| revocación/expiración/scopes durante ejecución | 401 / PREQUOTE_AUTHORIZATION_CHANGED | Terminal; no publicación |
| capacidad deshabilitada | 503 / PREQUOTE_DISABLED | Sin plazo administrativo conocido; no Retry-After |
| A5 no disponible | 503 / PREQUOTE_CONSUMPTION_UNAVAILABLE | Sin reserva ni intento. Retry-After sólo si admit devuelve fecha justificada |
| fallo inesperado sanitizado | 503 / PREQUOTE_EXECUTION_FAILED | Intención reintentable hasta presupuesto; terminal → PREQUOTE_FAILED |

Fallo terminal de negocio 422/401 conserva su código y mensaje de intención terminal. Configuración/lease terminal se traduce a PREQUOTE_FAILED. Una key exitosa nunca se renueva; una terminal no se reabre. No se debe generar automáticamente una key nueva para eludir presupuesto. Nueva key corresponde a una nueva intención explícita.

Ejemplo de emisión bloqueada (requestId/timestamp ilustrativos):

```json
{
  "statusCode":503,
  "code":"PREQUOTE_DISABLED",
  "requestId":"00000000-0000-4000-8000-000000000001",
  "message":"Service unavailable",
  "errors":[],
  "timestamp":"2026-09-28T18:00:00.000Z",
  "path":"/api/v1/delivery-prequotes"
}
```
