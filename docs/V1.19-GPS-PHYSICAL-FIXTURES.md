Destinatario GET `/shared/delivery-tracking` con cabecera Tracking privada, nunca token en URL API. Ambos pueden ver GPS desde las fases iniciales PICKED_UP/AT_DROPOFF; antes de publicar, sample=null/NO_SAMPLE. GPS y enlaces no constituyen prueba de custodia, entrega ni cobro.

Después de vencer, coordinar emisión explícita autorizada; no cambiar fechas ni emitir automáticamente. Los servicios ya asignados no se renuevan al iniciar el entorno.

Límites sin aumentar: IP60/min, Driver30/min, titular60/min, destinatario12/min, mutaciones de enlace5/10min; respetar429/Retry-After. Objetivo15s no es promesa de continuidad. ## Operación exclusiva

```powershell
node scripts/prepare-native-v119-gps-physical.mjs start
node scripts/prepare-native-v119-gps-physical.mjs verify
node scripts/prepare-native-v119-gps-physical.mjs snapshot
node scripts/prepare-native-v119-gps-physical.mjs observe
node scripts/prepare-native-v119-gps-physical.mjs stop
```

`verify` sólo antes del consumo; rechaza muestras o estados consumidos sin imprimirlas. Después, usar snapshot/observe y evaluar deltas. `start` exige puertos libres e identidad SQL/datadir/launcher propios; `stop` valida PID/launcher antes de detener y conserva datos. Si ya hay listener, comprobar identidad; no matar ni duplicar procesos. `init` sólo se usó sobre directorio nuevo. Repetir prepare completo sólo verifica, no reconstruye escenarios; resultados inciertos conservan marcador y detienen herramienta.

`observe` consulta ambas audiencias desde anfitrión y guarda únicamente fase, versiones, disponibilidad, precisión y fechas, sin coordenadas. Consume cuotas; no hacer polling adicional intenso mientras APP prueba. Enlace expirado/revocado devuelve error, no reemisión. `snapshot` consulta PostgreSQL read-only y conserva once huellas operativas más intentos/enlaces/cuotas y metadata GPS. En DeliveryLocationHead excluye sample, sampleHash y openReceipt antes de calcular huella; sólo incluye presencia, precisión/fechas y versiones. No es igualdad de coordenadas; es evidencia deliberadamente sanitizada.

## Privacidad y límites

Inspección del código: HTTP registra método/ruta parametrizada/status/duración/requestId, sin cuerpos/headers; errores omiten SQL y mensajes privados; limpieza GPS registra sólo evento/conteo. Prisma sin logging de consultas. Configuración únicamente del clúster nuevo: log_statement=none, log_min_error_statement=panic, log_parameter_max_length=0, log_parameter_max_length_on_error=0; evita volcar SQL/parámetros con posición real en errores. Los errores siguen registrados, se omite su sentencia. No se modificó logging global ni producto.

No se ha probado con GPS real durante preparación. No copiar logs crudos, dumps, contactos, tokens, enlaces ni coordenadas a evidencia pública. El backend conserva la última muestra en la base privada según contrato; PostgreSQL/WAL pueden conservar restos después de borrado lógico. No se acredita borrado seguro de disco, backups ni retención física; no exportar esa base como evidencia. Detener procesos suspende el worker de limpieza, aunque las lecturas posteriores deben respetar frescura al reanudar.

GPS puro no cambia hitos, custodia, ledger ni cobros; REPORT/DELIVER producen deltas legítimos. Separar cuotas, metadata y sesiones. APP acreditará de forma independiente permisos/fabricante, bloqueo30min, intervalos, batería, red, revocación, force-stop y cierre real. No confundir preparación administrativa ni evidencia previa de emulador con prueba física. Al terminar APP detiene sólo este entorno y retira el reverse creado, conservando datos.
